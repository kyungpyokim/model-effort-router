# Fast Path (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 단순 조회와 사소한 수정을 Plan/Review 없이 저비용 모델 단독으로 처리하는 Fast Path를 추가해, Phase 1 워크플로우가 만든 “작은 작업에서도 Sol/Opus 2회 호출” 비용 역전을 없앤다.

**Architecture:** 새 `inspect` task_type(read-only 조회)과 `trivial_edit` 경로(L1 + 엄격한 gating + 결정적 검사)를 `route()`에서 결정하고 route JSON에 `fast_path` 키로 싣는다(schema v6 유지, 추가 키). Fast Path 조건이 아닌 모든 코드 변경은 L1이라도 Phase 1의 정규 워크플로우(Plan→Implement→Test→Review)로 간다. 결정적 검사가 설정되지 않았으면 trivial edit는 성립하지 않는다.

**Tech Stack:** Python 3 stdlib, `unittest`/pytest (기준선 360 passed, 클린 트리), JSON config, bash launchers.

## Global Constraints

- `unknown`은 yes/risk/난이도 신호가 아니다. `unknown`이 남은 fact는 **Fast Path 조건 미충족**으로만 작용하고(정규 경로), 상위 모델 재분류·레벨 상향은 하지 않는다. 비선택 fact가 unknown이면 라우터가 이미 `unresolved_facts`로 거부하므로, 해결된 route에서 unknown일 수 있는 fact는 `requires_code_understanding`(선택 fact)뿐이다.
- Fast Path는 토큰 절감을 위한 예외 경로이지, 판단이 필요한 작업을 싸게 처리하는 우회로가 아니다. 위험(risk tier ≠ standard)·레벨 초과·`requires_code_understanding != no`이면 Fast Path 금지.
- Read-only Inspect는 `read` 권한만(Claude: `--disallowedTools Edit Write NotebookEdit Bash`), Plan/Implement/Test/Review 없음. Trivial edit는 구현 모델 수정 + launcher의 결정적 검사, Review 없음, 검사 실패 시 Fix 한도(`max_test_fixes` 2) 후 중단(상위 승격 없음).
- Codex Fast Path 모델: Luna Low(inspect) / Luna Medium(trivial edit L1). Claude: Haiku. Luna XHigh/Max·Sol/Opus는 Fast Path에서 사용 금지.
- 분류기: Codex Luna **Low**, Claude **Haiku**.
- 모델 ID는 `config/model-map.json`이 단일 출처. 번들 루트의 `scripts/`·`config/`·`references/`만 편집하고 `python3 scripts/sync_bundle.py`로 plugin 사본을 동기화한다. 훅(`routing_policy_hook.py`)·skill·README는 plugin-local.
- `SCHEMA_VERSION = 6` 유지. route JSON에는 추가 키 `fast_path`(`"inspect"` / `"trivial_edit"` / `null`)만 더한다. 이전 route 파일(`fast_path` 없음)은 그대로 검증·실행된다.
- 요청 범위 보존: 조회 요청을 수정으로 확대하지 않는다(분류기 프롬프트·skill·훅에 명시).
- 테스트는 hermetic: 외부 repo의 git 상태, `~/.cache/model-effort-router`, 추적 파일에 의존/기록하지 않는다. `router.main`을 호출하는 테스트는 `MODEL_EFFORT_ROUTER_STATE_DIR`를 임시 디렉터리로, `MODEL_EFFORT_ROUTER_SESSION`은 제거한다. 전체 pytest는 **클린 트리에서** 0 failed여야 한다(커밋 후 실행, 실행 후 `git status --short`가 비어야 함).
- 커밋 형식 `<type>: <description>`, 각 커밋 끝에 `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.
- 범위 밖: Fix 모델 난이도별 선택·독립 reviewer(Phase 3), 역할별 프롬프트·schema v7(Phase 4a), 지표(Phase 4b).

## 설계 결정 (근거)

1. **Trivial edit = 새 경로가 아니라 “L1의 엄격한 부분집합 + 검사 강제”.** `mechanical_only=yes`인 route가 L1이 되고(모든 위험 fact가 명시적 no여야 함 — `DIFFICULTY_RULES`), 비선택 fact가 unknown이면 이미 거부되므로, L1 route는 `files_touched=1`, crosses_* = no, security/API/persisted = no, blast narrow가 명시된 상태다. 추가 gating은 `risk_tier == standard`, `requires_code_understanding == "no"`(명시), `task_type ∈ {implementation, local_refactoring}`, 결정적 검사 존재뿐이다.
2. **결정적 검사 존재 = 라우트 시점의 `MODEL_EFFORT_ROUTER_TEST_CMD` 환경변수.** 라우터와 pipeline이 같은 변수를 읽는다(`router.TEST_COMMAND_ENV`, pipeline이 재사용). 설정이 없으면 L1 코드 변경도 정규 워크플로우(Plan+Review가 검증을 대신한다). 자동 감지(pytest.ini/package.json 등)는 YAGNI — 필요해지면 후속으로.
3. **정규 워크플로우의 판사 행은 `max(level, L2)`.** Fast Path가 아닌 L1 코드 변경의 planner/reviewer는 L2 `design`/`review` 행(Sol/Opus)을 쓰고, 구현자는 실제 레벨 행을 쓴다. Phase 1의 `PLAN_MIN_LEVEL`/`REVIEW_MIN_LEVEL`(레벨 게이트)은 `WORKFLOW_MIN_LEVEL = "L2"`(판사 행 하한) 하나로 바뀌고, “L1은 계획/리뷰 없음” 규칙은 `fast_path == "trivial_edit"` 규칙으로 바뀐다.
4. **`inspect`는 L1/L2 standard tier에서만 성립한다.** 레벨 > L2 또는 tier ≠ standard이면 라우터가 해당 분류를 거부한다. 호출자는 판단 작업을 `review` 또는 `design`으로 다시 분류해야 하며, 라우터가 Sol/Opus로 자동 승격하지 않는다. 매트릭스의 inspect L3~L5 행은 완전성 검사용이며 도달 불가.
5. **route reuse의 INSPECT→MODIFY 전환 blocker는 이미 존재**(`route_reuse.reuse_blockers`의 `operation changed`). 이번에는 `inspect` task_type이 그 로직에서 read-only로 취급되는지 테스트로 고정만 한다.

```python
INSPECT_MAX_LEVEL = "L2"
TRIVIAL_EDIT_TASK_TYPES = ("implementation", "local_refactoring")


def fast_path_for(task_type: str, level: str, risk_tier: str, facts: dict[str, str], check_available: bool) -> str | None:
    """The cheap single-model path a route qualifies for, or None for the regular workflow.

    Only an explicit ``requires_code_understanding == "no"`` qualifies a code change: unknown is missing
    information, so it keeps the regular workflow without raising anything."""
    if task_type == "inspect":
        return "inspect"
    if (
        task_type in TRIVIAL_EDIT_TASK_TYPES and level == "L1" and risk_tier == "standard"
        and facts.get("requires_code_understanding") == "no" and check_available
```
