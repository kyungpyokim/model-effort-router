**Codex 기존 개발 대화에서 실제 요청 후보 25개와 빈 사람 검수 시트를 준비했다.** 사용자가 이 25개를 직접 검수하기로 했다. 현재 사람 정답 0개, 새 분류 live 호출 0회이며 실제 요청 정확도 비교는 미실행이다.

## 수집과 선별

사용자가 지정한 Codex 개발 대화의 로컬 원문을 사용했다. `source=vscode`, `thread_source=user`인 개발 프로젝트 세션만 수집하고 현재 평가 대화, exec·하위 에이전트·fixture/runs/spikes 세션은 제외했다.

| 단계 | 개수 |
|---|---:|
| 수집 범위의 대화 세션 | 23 |
| 초기 필터 이후 메시지 | 146 |
| 같은 원문 중복 제거 | 14 |
| 고유 후보 | 132 |
| 독립 입력 후보 | **25** |
| 선행 맥락 필요 | 83 |

두 검토 에이전트가 서로 다른 ID 구간을 선별했으며 정답은 붙이지 않았다. 선택된 25개는 13개 대화에서 나왔고 기존 `model-effort-router` 저장소 14개, 현재 저장소 11개다. **목표 100~200개에는 미달하며 라우터 프로젝트에 편중됐다.** PR 참조나 넓은 테스트 요청도 포함하므로 최종 정답 코퍼스가 아닌 후보 집합이다.

원문을 요약·의역하지 않았고 경로를 추측하지 않았다(`paths=[]`). 선행 맥락을 합성하지 않았다. 25개 모두 원본 기록 위치와 대조했고 8,000자 이하이며 잘라내지 않았다. 검토에서 명백한 비밀 값은 발견하지 못했다. 개인 원문·출처는 Git에서 제외된 `runs/`에 보관하고 공개 코퍼스에 합치지 않았다.

## 직접 검수

[25개 검수 시트](../../runs/real-holdout-human-review-20261005.tsv)의 정답 필드는 모두 비어 있다. 분류기 예측이나 추천 정답은 제공하지 않는다. [라벨링 가이드](labeling-guide.md)에 따라 다음을 채운다.

- `level`: L1~L5. `target=no_route`이면 비워 둔다.
- `risk_flags`: 없으면 `[]`, 있으면 JSON 배열(예: `["auth"]`).
- `target`: route / plan_only / review_only / no_route.
- `human_reviewer`: 실제 검수자. 불명확하거나 제외할 항목은 `note`에 사유를 적는다.

현재 코퍼스는 전부 `draft`, labels는 빈 목록이고 final은 없다. 사람 검수와 기존 독립 라벨·불일치 합의 절차를 거친 뒤 평가한다. AI 검토를 사람 검수로 기록하거나 분류기 결과를 정답으로 쓰지 않는다.

## 후속 비교

사람 검수가 완료되면 입력·정답 해시를 고정하고 기존 연쇄·지표 함수를 재사용한다. Jev 단독 baseline과 이전에 고정한 조건부 guide 연쇄를 같은 요청으로 새 호출한다. 이는 두 운영 후보의 비교이며 질문을 통일한 연쇄 구조 단독 효과 비교가 아니다. 요청별 두 arm의 순서는 고정 seed로 교차 배치한다.

정확도·critical miss·target, Jev 선택률·실패, arm 전체 지연과 backend별 토큰을 기록한다. 가격·청구 자료 없이 금액 절감을 주장하지 않는다. 25개만 실행하면 소규모 파일럿으로 명시하며 100~200개 목표나 일반화 검증을 완료했다고 보고하지 않는다. 제품·설정·합성 코퍼스는 유지했다.
