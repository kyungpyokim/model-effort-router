# Laya 코퍼스 성능 측정 (2026-10-08)

Laya 0.4.0을 로컬 MPS에서 실행해 adjudicated v3 150건을 당시 `LayaBackend` 요청 형식 그대로 분류했다. 150건 모두 HTTP 200으로 응답했고 role 90건(60.0%), effort 38건(25.3%), role·effort 동시 30건(20.0%)이 다수결 라벨과 일치했다. 이 값은 독립적인 사람 정답 정확도가 아니라 기존 다수결과의 일치율이다.

| 항목 | 결과 |
|---|---:|
| 코퍼스 | `role-effort-human-holdout-v3-adjudicated.jsonl`, 150건 |
| role | 90/150 (60.0%) |
| effort | 38/150 (25.3%) |
| 동시 일치 | 30/150 (20.0%) |
| 요청 성공 / 오류 | 150 / 0 |
| 왕복 지연시간 | p50 50.8 ms (median), p95 103.5 ms (nearest rank), 최대 195.3 ms |
| 요청 alias → 모델 / checkpoint | `laya` → `laya-rl-agent` / `english` (`convaiinnovations/laya`) |
| checkpoint revision | `7b928d828b7b0e022f929d9bd2e44165aa270148` |
| 실제 device | MPS (fallback 0회) |
| 사용량 | 입력 82,300 tokens, 출력 0 tokens |
| 응답 truncation | 0/150 |

지연시간은 모델을 미리 로드한 뒤 측정한 sequential HTTP 요청 왕복시간이다. 최초 모델 로딩, 프로세스 시작, 다운로드는 포함하지 않았다. 측정 전 기본 backend로 보낸 사전 확인 요청 1건은 `plan/max`, 432 input tokens였고 본 150건 점수에는 포함하지 않았다. 정식 요청의 task와 paths만 전송했으며 gold label은 보내지 않았다. 당시의 `QUESTIONS`, `state_text`, 기본 `LayaBackend` 모델 선택(`laya` alias)을 사용했다. Laya server는 이 alias를 매 요청 `english`로 해석했다. 다국어 자동 라우팅 성능을 측정한 것은 아니다. 이 실행에서는 prompt와 backend 구현을 바꾸지 않았다. fallback을 쓰지 않았고 각 요청 timeout은 30초다. 150건 모두 usage의 `truncated=false`였다.

role 정답 일치는 review 26/39, fix 26/34, analysis 8/19, implementation 17/33, plan 11/18, lint 2/6, design 0/1이었다. effort는 high 17/30, medium 19/24, low 1/83, xhigh 1/13이었다. test role과 max effort gold는 코퍼스에 없으므로 해당 분류값의 성능은 측정하지 않았다. 주요 혼동은 gold low를 high 31건·medium 39건·max 10건으로 예측한 점, 그리고 gold implementation 33건 중 fix 11건으로 예측한 점이다. 전체 gold→prediction confusion matrix와 건별 예측은 원시 결과 JSON에 있다.

## 해석 한계와 재현 정보

v3는 Jev/Nimble 및 OpenAI Decisions 평가에 이미 사용된 세트다. 다섯 시트의 다수결을 기준으로 계산했으며 판정자 독립성은 검증되지 않았다. 따라서 이번 수치는 새롭고 독립적인 정확도 추정이 아니며, 코퍼스 분포를 벗어난 요청의 성능을 말해주지 않는다. 비교 결과는 각 provider와 시점의 별도 기록이며 서로 같은 평가 조건의 속도 비교로 해석하지 않는다.

- 결과와 재계산 가능한 건별 근거: [`laya-v3-20261008.json`](laya-v3-20261008.json)
- 코퍼스 SHA-256: `9a9c4f4646452342e403a7a73815b64d36599106d7e794347343c7c44e1372ea`
- Laya package `0.4.0`, torch `2.14.1`, Python `3.13.15`; macOS arm64
- git HEAD: `a133ec8ffd123dc9ab49e0f2749e6ecf1cf047aa`; 작업 트리는 다른 미커밋 변경을 포함했다. `QUESTIONS` SHA-256과 실행 후 backend 파일 SHA-256 및 서버 health 응답은 JSON metadata에 기록했다. 완전한 실행 전 backend hash 증거는 보존되지 않았다.
- 공식 wire/API 설명: [Laya HTTP API](https://nandhakishorm.github.io/laya/http-api/).
- 이 실행은 Python `3.13.15`, `laya[serve]==0.4.0`, `torch==2.14.1`을 사용했다. 격리된 venv/cache로 서버를 띄우고 기존 `evaluation.compare.evaluate_backend` helper로 점수를 재현하려면 저장소 루트에서:

  ```sh
  uv venv --python 3.13.15 runs/laya-eval-venv
  uv pip install --python runs/laya-eval-venv/bin/python 'laya[serve]==0.4.0' 'torch==2.14.1'
  mkdir -p runs/laya-hf-cache
  ```

  한 터미널에서 서버를 띄운다:

  ```sh
  HF_HOME="$PWD/runs/laya-hf-cache" LAYA_HOST=127.0.0.1 LAYA_PORT=8000 LAYA_PRELOAD=0 LAYA_THREADS=4 runs/laya-eval-venv/bin/laya-serve
  ```

  두 번째 터미널에서 같은 150건의 role/effort 점수를 확인한다:

  ```sh
  PYTHONPATH="$PWD" MER_CORE_PATH="$PWD" runs/laya-eval-venv/bin/python - <<'PY'
  from evaluation.cases import load
  from evaluation.compare import evaluate_backend
  from model_effort_router.difficulty.decision import DifficultyInput
  from model_effort_router.difficulty.laya import LayaBackend
  from model_effort_router.difficulty.jev import QUESTIONS

  class EnglishBaselineBackend(LayaBackend):
      # Keep this historical run on the shared QUESTIONS prompt.
      questions = QUESTIONS

  rows = load("evaluation/corpus/role-effort-human-holdout-v3-adjudicated.jsonl")
  backend = EnglishBaselineBackend(model="laya", options={"url": "http://127.0.0.1:8000/v1/systemone"})
  backend.classify(DifficultyInput("Plan the implementation"), 30)  # 모델 로딩 확인, 점수에서 제외
  result = evaluate_backend("laya", backend, rows, timeout_s=30)
  print({key: result[key] for key in ("n", "role_exact", "effort_exact", "joint_exact", "errors", "latency_ms")})
  PY
  ```

  이 코드는 현재의 compact Laya 질문을 그대로 쓰지 않고 `QUESTIONS`를 지정해 당시 영어 baseline 질문을 재현한다. 현재 `LayaBackend` 기본값으로 실행하면 compact 지시문으로 다시 평가하는 것이므로 기존 점수 재현이 아니다. 기본 모델과 URL을 명시해 환경 변수 재정의의 영향을 막고, 별도 요청으로 모델을 로드한 뒤 본 코퍼스를 측정한다. `evaluate_backend`는 median/p50과 최대 지연을 반환한다. 이번 실행의 p95 nearest-rank, usage, 모델/revision과 건별 응답은 연결된 원시 JSON에 보존했다. setup 명령은 package 버전을 고정하지만 checkpoint 다운로드는 실행 시 최신 revision을 선택할 수 있으므로 서버 health의 revision도 위 기록과 비교해야 한다.

이 측정은 현재 다수결 기준과의 낮은 일치, 특히 low effort 분류의 큰 편향을 보여준다. 여기서는 원인을 고치거나 prompt를 조정하지 않았다. 조정 후 성능을 주장하려면 새 holdout에 대한 평가가 필요하다.
