# 세션 맥락 A/B: Jev target·role·effort (2026-10-07)

실제 세션의 후속 요청을 Jev로 두 번씩 분류했다. A는 현재 프롬프트만, B는 훅과 같은 방식으로 만든 세션 맥락을 함께 보냈다. 맥락을 주면 target 판단이 34/60에서 47/60으로, route 케이스의 target+role 동시 정확도가 22/56에서 37/56으로 올랐다. 개선은 30자 이하의 짧은 후속 요청에 집중됐다.

## 설정

- 표본: 로컬 Claude Code transcript와 Codex rollout에서 이전 assistant 턴이 있는 user 턴을 뽑았다. 30자 이하 짧은 요청 1,334건 중 40건, 그보다 긴 요청 273건 중 20건을 seed `20261007`로 무작위 추출했다. Claude 38건, Codex 22건이며 이 저장소 외 다른 프로젝트 세션도 포함된다.
- 맥락(B): `context.summary.build_context("", 이전 턴, 6000)`. 저장된 세션 요약 없이 최근 user/assistant 텍스트만 6,000자 예산으로 넣었다. tool 출력·system-reminder·호스트 주입 텍스트는 transcript 파서가 제외한다. 실제 Claude 훅은 세션 요약도 함께 보내므로, 오래전 계획을 가리키는 후속 요청에 대해서는 이 결과가 실제 효과를 과소평가한다.
- 분류기: `JevBackend`(target 질문 포함, PR #32 코드), timeout 12초, 120회 호출, 오류 0건.
- 정답: opus 라벨러 1명이 Jev 결과를 보지 않고 같은 맥락과 프롬프트로 target/role/effort를 붙였다. 사람 판정이 아니며 확신도 low가 4건이다.
- 전송 전 API 키·토큰 패턴을 검사해 해당 사항이 없음을 확인했다. 실제 대화 텍스트가 들어 있는 케이스·라벨·결과 파일은 저장소에 넣지 않았다.

## 남은 오류와 결정

B의 target 오답 13건 중 10건은 프로젝트에 관한 질문이다. 예를 들면 설정을 바꾸면 나아지는지, 특정 파일만 고치면 되는지 묻는 질문이다. 라벨은 route/analysis였지만 Jev는 no_route로 답했다. 처음 21건 수동 확인에서 틀린 2건도 같은 유형이었다.

**결정(2026-10-07): 이런 질문은 no_route로 둔다.** no_route면 훅이 조언을 내지 않고 Main이 대화 맥락을 가진 채 직접 답한다. 질문에 Subagent 위임을 권하면 비용만 늘고 Main 직접 처리 원칙과 충돌한다. 분석을 작업으로 요청하는 경우(예: "원인 파악해")는 그대로 route다. Jev 기준 문구는 바꾸지 않았다. 이 기준으로 보면 target 정확도는 A 46/60, B 57/60이다.

나머지 role 오답은 analysis/plan(다음 작업을 묻는 질문), implementation/design(재설계 선택지 승인), fix/implementation(라우팅 규칙 변경), git/PR 요청을 review나 analysis로 본 경우였다.

## 한계

- 라벨은 AI 라벨러 1명이 붙였다. 사람 판정이나 두 번째 라벨러의 독립 라벨로 확인하지 않았다.
- 라벨상 no_route가 4건뿐이라 no_route 정밀도는 거의 측정되지 않았다. 잡담·감사 인사 같은 명백한 no_route는 별도의 21건 수동 확인에서만 다뤘다.
- 세션 요약을 쓰지 않았다. 요약 경로를 포함한 측정은 백그라운드 `claude -p` live 검증 뒤에 한다.
