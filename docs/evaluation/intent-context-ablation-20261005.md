# L2 구현·리뷰 의도와 코드/diff 제공 여부: 192회 live 진단 (2026-10-05)

같은 변경 내용에서 요청 문구와 코드/diff 제공 여부를 바꾸면 Nimble의 L2 판정이 크게 달라졌다. 리뷰 조건에서 L2를 L3로 올려 잡았고, 코드/diff를 제공해도 개선되지 않았다. 이 표본에서 “코드가 없어서 리뷰 점수가 낮다”는 설명은 지지되지 않는다. 반면 모델이 요청 표현에 민감하다는 증거는 확인됐다. 구현+코드 조건에는 별도로 후처리 승격 오류도 있었다.

## L2 결과

각 행은 **독립적인 L2 예제 8개 × 동일 입력 2회**다. 16개의 독립 표본이 아니다. 아래는 제품의 후처리까지 거친 최종 레벨의 정확도다.

| 요청 · 제공 정보 | Jev 최종 L2 | Nimble 최종 L2 | Nimble 원점수 최빈 레벨 L2 | Nimble 오답 방향 |
|---|---|---|---|---|
| 구현 · 설명+경로 | 16/16 (100.0%) | 12/16 (75.0%) | 12/16 (75.0%) | L1: 4 |
| 구현 · 설명+경로+코드+diff | 16/16 (100.0%) | 10/16 (62.5%) | 12/16 (75.0%) | L1: 4, L5: 2 |
| 리뷰 · 설명+경로 | 16/16 (100.0%) | 4/16 (25.0%) | 4/16 (25.0%) | L3: 12 |
| 리뷰 · 설명+경로+코드+diff | 16/16 (100.0%) | 0/16 (0.0%) | 0/16 (0.0%) | L3: 16 |

- 설명+경로만 제공: 리뷰−구현은 최종 L2 정확도 **−50.0%p**. 코드/diff 제공: **−62.5%p**. 같은 기반 예제끼리의 비교다.
- 코드/diff 추가: 구현은 최종 정확도 **−12.5%p**, 원점수 정확도 변화 0.0%p. 리뷰는 최종/원점수 모두 **−25.0%p**.
- Jev는 네 조건 모두 L2 100%. Nimble의 L1·L3 대조군은 네 조건 모두 각각 4/4. 문제는 이 실험의 L2 경계에 집중됐다.
- 양쪽 모두 명시한 target 선택은 96/96 일치했다. 이는 prefix에 지정한 행동을 선택하는 검사이며, 명시된 리뷰 target을 선택해도 난이도 레벨이 틀릴 수 있음을 보여준다. 실제 사용자 표현의 target 정확도를 보장하지 않는다.
- 같은 입력 두 번 사이 최종 레벨·원점수 최빈 레벨·target 불일치: 양쪽 모두 0/48. 확률 전체의 결정론이나 다른 실행 환경에서의 재현성까지 보장하지 않는다.

## 모델 점수와 후처리 분리

Nimble 최종 오답 38/96 중 36건은 원점수 최빈 레벨부터 정답과 달랐다. 나머지 2건은 같은 콜백 예제의 두 반복에서 원점수 L2를 후처리가 L5로 승격했다. 리뷰 오답 28건은 모두 원점수부터 L3였다. 따라서 리뷰 하락을 승격 규칙 수정만으로 해결할 수 없다.

콜백 구현+코드 예제의 확률은 P(L2)=0.462829, P(L4)=0.006926, P(L5)=0.216557이었다. P(L4)+P(L5)=0.223483이 현재 `l4_promote_prob=0.2`를 넘어서 L5가 됐다. 이 승격은 위험 플래그가 켜져야 하는 규칙이 아니다. 변경은 순차 중복·재진입을 처리하는 국소 수정이며 스레드나 분산 처리 요구는 없다. 이 예제는 기존 v1 조정 표본 밖에서 드러난 잘못된 고난도 승격이다. 현재 `critical_miss`는 정답 위험 사례를 낮게 부르는 오류만 세므로 이런 과잉 승격을 드러내지 못한다. 이 한 예제만 보고 전역 임계값을 바꾸면 L4/L5 재현율을 해칠 수 있으므로 제품 설정은 유지했다.

## 실험 통제와 검증

- 호출 전 설계·질문·예제·순서를 고정했다. 새로운 합성 예제 12개(L1 2, L2 8, L3 2) × 2 의도 × 2 정보 조건 × 2 반복 × 2 backend = **192회** 새 live 호출.
- Jev 응답 모델 `jev-1.13.0`: 96회 HTTP 200. 로컬 Nimble 응답 모델 `nimble`: 96회 HTTP 200. 양쪽 fallback 0, 통신 오류 0.
- 기존 보강 질문 `live-guide-level-question-20261004.json`을 그대로 사용했다. 기각한 새 L2 문구는 사용하지 않았다. 다른 질문과 제품 임계값은 그대로다.
- 같은 코드와 최근 diff를 양쪽 의도에 똑같이 제공했다. 최근 diff는 현재 버그가 있는 코드를 만든 변경이다. 참조 수정 코드와 실행 검사는 모델에 보내지 않았다. 설명+경로 조건에는 코드를 보내지 않았다.
- 모든 호출에서 실제 payload state가 예정된 입력 전체와 동일함을 확인했다. 최대 task 1,251자: 제품의 4,000자 제한으로 인한 잘림이 없다.
- backend당 같은 seed 20261005의 섞인 96개 순서를 순차 호출했다. backend 두 개만 병렬 실행했다. 반복 조건은 입력이 같고 별도 모델 seed는 설정하지 않았다.
- 코드 예제 12개 모두 기존 버그 재현과 참조 수정 실행 검사를 통과했다. Python 검토자는 예제·검사·diff 사이 실험을 무효화할 불일치를 발견하지 않았다.
- 두 독립 AI 라벨러가 proposed·검사·모델 예측·서로의 라벨을 보지 않고 중립 설명+경로+코드를 검토했다. 12/12 레벨·위험 플래그·중립 target이 일치했다. 의도별 target은 명시한 요청 조건에서 부여했다.
